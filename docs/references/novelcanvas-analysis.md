# NovelCanvas 사례 분석

## 목적

NovelCanvas를 별도의 글쓰기·창작 프로젝트 참고 사례로 기록하고, ANE Context AI의 Research Space 인터페이스 설계에 적용할 수 있는 제품 원칙을 분리해 정리한다.

## 핵심 요약

NovelCanvas의 중요한 지점은 단순한 AI 소설 생성이 아니라 아이디어, 설정, 본문, 검수, 이미지, 출판 준비를 하나의 작업공간 안에서 이어가려는 데 있다.

핵심 특징은 다음과 같다.

1. 채팅형 AI보다 창작 워크스페이스 중심이다.
2. 세계관·인물·설정 등을 본문과 분리해 관리한다.
3. AI는 작가를 대체하기보다 제안·검수·보조 역할을 맡는다.
4. 텍스트와 삽화 등 여러 창작 자산을 같은 문맥 안에서 관리한다.
5. 완성된 작품 이전에 창작 과정의 상태를 지속적으로 유지한다.

## Research Space에 주는 시사점

### 1. Context Dictionary

소설의 인물·장소·세계관·사건·관계를, 연구에서는 다음과 같은 객체로 바꿀 수 있다.

- 개념
- 주장
- 질문
- 가설
- 근거
- 출처
- 반론
- 실험
- 결론

본문과 지식 객체를 분리하면 문서가 길어져도 연구의 핵심 구조가 사라지지 않는다.

### 2. Creator-controlled AI

AI가 전체 결과를 대신 만드는 것보다, 사용자가 통제권을 유지하면서 특정 역할만 맡기는 방식이 적절하다.

예:

- 관련 자료 연결: 자동 가능
- 새 제안 생성: 자동 가능
- 기존 설정·주장 수정: 승인 필요
- 가설 채택·폐기: 승인 필요
- 문서 대규모 변경: 승인 필요

### 3. Integrated Workspace

창작 과정이 여러 도구로 분리되면 맥락이 쉽게 끊긴다. Research Space도 질문, 자료, 가설, 반론, 출처, 결과 문서를 하나의 상태 있는 작업공간으로 묶는 것이 핵심이다.

## 단순 복제하면 안 되는 부분

NovelCanvas는 최종적으로 완성된 소설 문서를 중심에 둔다. Research Space에서는 반대로 문서를 최종 View로 취급해야 한다.

```text
Research Space
  → 탐색 / 분기
  → 근거 / 반론
  → 구조화
  → Manuscript / Report / Explanation
```

즉 문서가 원본 데이터가 아니라 구조화된 사고·연구 공간의 투영 결과다.

## 제품 원칙

1. 문서와 지식 구조를 분리한다.
2. AI 응답을 채팅 로그가 아니라 노드·관계 변경으로 남긴다.
3. 사용자 승인 경계를 명확히 둔다.
4. 폐기한 가설과 이전 상태까지 연구 이력으로 보존한다.
5. 3D 그래픽보다 다차원 정보 모델을 먼저 검증한다.

## ANE Context AI와 연결

ANE Context AI가 이미 지향하는 질문별 Context Package, 증거·해석·논쟁·불확실성 분리, 지식 그래프 구조는 Research Space의 핵심 데이터 모델과 직접 연결된다.

NovelCanvas에서 가져올 것은 “창작자가 여러 도구를 오가지 않게 하는 통합 작업공간 UX”이며, ANE Context AI에서는 이를 “연구자가 질문에서 출처·가설·반론·문서까지 추적 가능한 연구 IDE”로 확장한다.

## 결론

NovelCanvas의 가장 중요한 참고점은 AI 모델이 아니라 상태 있는 작업공간이라는 제품 구조다.

> 글을 쓰는 화면이 아니라, 창작과 사고의 상태를 보존하고 조작하는 작업공간을 만든다.

이 원칙은 소설뿐 아니라 연구, 기획, 장문 글쓰기, 세계관 구축, 시나리오 작성에도 확장 가능하다.
